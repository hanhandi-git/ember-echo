# 战斗手感：从《哈迪斯》提炼的本轮改造

目标是让玩家清楚感到「按下就出手、接触有阻力、敌人被打动、收招能接下一步」。以下是对《哈迪斯》可观察战斗表现的设计拆解，不代表其内部实现，也没有把本项目参数当成《哈迪斯》的实测值。

## 可以借鉴的经验

| 《哈迪斯》的体验 | 可复用原则 | 余烬回响本轮落地 |
| --- | --- | --- |
| 出手快，闪避、普攻与走位能串起来 | 先解决输入响应和动作衔接 | 单次 160ms 输入缓冲、按住连斩、闪避取消普攻；闪避尾段可接强化斩 |
| 武器挥空与砍中差别很大 | 挥动音属于出手，撞击音、停顿属于接触 | 出手保留轻挥刀声；真正命中才触发停顿、冲击环、碎屑与命中音 |
| 连段有重音，收尾能清出空间 | 重击价值来自节奏和敌人反应 | 三段有独立前摇与收招；末段范围略长、最多扫到三人（武器原有更高穿透数保留）、击退更强 |
| 普通敌人受击明显让位，强敌能顶住攻击 | 击退与硬直是可感知的战斗结果 | 小怪短硬直打断起手和已排队的近战反击；Boss 不增加受击硬直，击退按 15% 并封顶 |
| 命中瞬间集中、随后迅速消散 | 将反馈能量压在接触附近 | 局部十字冲击、扩散断弧、定向火花、轻微体型回弹、血条金色残量、伤害数字弹出 |
| 连续战斗仍能读到敌人和弹幕 | 强弱分层、限制覆盖和累计 | 轻击短停顿，小群同帧命中取最大值；重击用独立短低频撞击音；常规普攻不用全屏闪光 |

《哈迪斯》的装甲、背刺、祝福组合、敌人配置和关卡节奏同样影响爽感。本轮聚焦现有战斗反馈链，未增加这些整套机制。当前 `defense` 仍表示减伤数值，不能直接当作装甲韧性使用。

## 原来的主要问题

1. 第三段在 100ms 结算伤害，人物却到 280ms 才落刀；动作还会持续到 1.15 秒，容易出现「没砍到就扣血」的感觉。
2. 三段共用 260ms 冷却，冷却内按键直接被拒绝；没有按住连斩，快按容易断节奏。
3. 小怪受击后仍可能继续攻击；有死亡姿态的小怪还会被当作活目标再次命中。
4. `flashScreen` 把透明度除以自身初始值，首帧始终接近完全不透明，还覆盖 HUD；提示和敌人瞬间消失。
5. 投掷物额外重复显示数字和命中音；火球接触后继续存在，可能重复爆炸；爆炸投掷物先把直击目标加入排除列表，导致漏伤害。
6. 缺蓝反馈函数与同名状态字段冲突，会抛异常；被拒绝的技能还会先打断正在演出的技能。

## 本轮参数与入口

主调参入口：`src/combat-feel.js`。时间单位为秒，位移与震幅使用 320×180 战场坐标；人物/刀光的美术距离仍按 `COMBAT_SCALE` 缩放一次。

| 普攻段数 | 接触时间 | 下一段可用 / 动作结束 | 伤害基值 | 击退速度 | 命中停顿 | 小怪硬直 |
| --- | --- | --- | --- | --- | --- | --- |
| 一段 | 65ms | 240ms | 11 | 38 | 28ms | 150ms |
| 二段 | 85ms | 280ms | 14 | 46 | 38ms | 190ms |
| 三段 | 170ms | 430ms | 24 | 100 | 62ms | 290ms |

- 攻速较快的武器（移速档 ≥72）使用 0.86 倍动作时长，较重的武器（≤55）使用 1.13 倍；只是本轮的粗分档，后续可按武器配置独立攻速。
- 会心或击杀只额外增加 12ms 命中停顿；同一批群体命中使用最大时长，不逐个累计。灼烧等持续伤害不触发硬直、击退或停顿。
- 闪避之后 0.5 秒内接普攻，该次伤害 ×1.15，使用重击反馈与小群扫击；闪避本身不再常规震屏。
- 镜头使用有方向的衰减振动，Y 轴幅度较低；全屏染色透明度最高 0.22，画在 HUD 之前。
- 两个以上大型前景法术叠加时，重绘主角的真实骨骼与细暗边轮廓，避免雷柱和陨石把玩家完全淹没。此处理只影响渲染，不改变碰撞或深度判定。
- `impactHeavy` 的瞬态、低频主体与短金属尾音在接触帧播放。背景音乐独立衰减到 0.56，80ms 后平滑恢复；轻击只轻微压到 0.9。用户音量设置不被改写。

## 引擎接入地图

本项目使用自定义 Canvas 游戏循环与同级 pixelfx 库，保持现有引擎和素材契约。

| 职责 | 实际接口 |
| --- | --- |
| 构建、启动、验证 | `npm run build`、`npm start`（8123）、`npm run lint`、`npm test` |
| 输入与时间 | `installKeyboard`、触屏 `pressed` 指针集合 → `castSkill` / `updateCombatInput`；`Game.tick(dt)` 使用秒；停顿期间不消耗普攻缓冲 |
| 普攻与取消 | `castJ` 持有本次动作对象，伤害计时器检查其身份和取消标记；`Hero.cancelMelee`、闪避、受伤、换关卡负责失效 |
| 命中反馈 | `Enemy.hurt` / `Boss.hurt` → `impactFeedback`；`IMPACTS` 集中定义反馈层次 |
| 视觉与音频 | `src/fx/melee-swing.js`；`drawImpacts`；`AudioEngine.play/duck`；镜头只改渲染偏移，不改碰撞坐标 |
| 生命周期与存档 | `loadStage` 清空瞬态反馈、计时器与按键；战斗反馈对象不写入存档 |

## 普攻姿态与特效改造

普攻改为复用 pixelfx 的完整近战演出，默认三段为低位拔刀、反手交叉双斩、全身回旋收尾。`src/fx/ember-draw.js` 在 pixelfx 的 `weaponAttack` 构造器上新增宽刃拔刀变体；交叉斩与回旋斩直接使用库内的材质、粒子与光照。人物用相同来源的 `act.poses` 做踏步、扭胯、转身和收招，画出的武器始终是实际装备。

`src/melee-arts.js` 按武器分为剑、太刀、镰、棍、突刺、爪、重击与圣剑八种演出。回旋刀光分背面与前面绘制，身体残像最多三个、120ms 消散；脚下扬尘在出力时出现。普通攻击仍使用原有伤害、节奏与输入缓冲，库内稻草人命中、预览停顿与位移不参与游戏判定。

姿态与特效通过同一个 `meleeSourceTime` 时钟映射到 `MELEE_BEATS`：前摇压缩到当前接触帧，保留短暂出刀余势，再加快收招与粒子消散。太刀、棍、刺剑保留不同的握法；重锤使用抡锤、重劈、震地收尾。闪避可同时取消身体残像与特效前后两层，避免出现已收招还在出刀的画面。

调姿态时先改演出分组或源姿态，调攻击节奏仍改 `combat-feel.js`；不要单独修改一套计时而让伤害早于可见接触。新增演出应检查左右方向、当前造型、持续移动、特效结束为空、种子确定性与取消后的两层残留。

## 可复用的调优流程

可以把这一节作为后续手感任务的操作指南，配合已有 `game-feel` skill 使用。

1. **先对齐接触帧。** 逐段看输入、抬手、刀锋抵达、扣血、命中音、敌人后退。不要只用伤害数字证明命中正确。
2. **先调输入，再调特效。** 检查提前按键、停顿中按键、长按、松开、闪避取消、按键映射与触屏。缓冲最多保存一个动作。
3. **先分事件，再加重量。** 空挥、轻击、重击、会心、击杀、Boss 受击分别调参；持续伤害保持安静。
4. **让敌人替攻击说明力度。** 验证击退方向、起手中断、死亡目标退出，以及重敌不被永久硬直。已发出的弹体保留；尚未结算的被中断近战取消。
5. **同步声音，给命中留空间。** 关键瞬态落在接触帧；用独立总线轻微压低背景声，避免简单放大所有音效。
6. **用密集战斗审查可读性。** 群体命中停顿不累加，限制残留数量，确认英雄、敌人预警、HUD 与来袭弹体可见。
7. **用实际操作验收。** 同一个场景分别用长按、点按、走位连斩、闪避接斩体验，再测试低法力、暂停恢复、死亡和换关卡。自动化测试负责判定与生命周期；主观爽感由试玩继续微调。

## 本地验收清单

- 桌面：按住 J 连段、松开停止、提前点按与停顿中点按、攻击中 Q 取消、Q 接 J、第三段群体命中。
- 敌人：受击中断哥布林前摇和延迟近战、灼烧不打断、Boss 受击不被强制停招、死亡姿态不重复计数。
- 技能：K 单次爆炸、T 直击目标、法力不足不报错且不打断已有动作；霜环、雷罚和陨星的原有范围/预警仍可见。
- 画面：观察接触帧和收招帧，以及多人命中的密集状态；对比桌面 1280×800 与触屏横屏 844×390，确认画布、HUD、操作热区完整。
- 声音：重击区别于空挥；短暂背景压低会恢复；静音、背景音乐音量与音效音量仍独立。
- 回归：`npm run lint`、`npm test`、`npm run build`；改造保留在本地供检查，不自动发布。

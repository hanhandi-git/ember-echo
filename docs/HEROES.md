# 人物与动作帧

游戏沿用 Canvas / pixelfx 渲染器，入口是 `src/main.js`。`Hero` 管理人物状态，`castSkill()` 管理伤害与技能时序，`createSettingsUI()` 管理选择界面，存档继续使用 `ember-echo-save`。

## 攻击与法术

- J 为三段普攻，闪避后接 J 使用强化动作，伤害增加 15%。游侠和法师使用动作图中的释放帧发射远程攻击；飞行效果也裁自人物原动作。
- 剑士的 T 改为强化普攻，不再装备或投掷外部武器。玩家输入已精简为 J 普攻 / K 格挡 / L 千鸟突进三键（`src/quick-bar.js`，跨职业）；技能槽配置仍保留给自动战斗，剑士近战剑技也统一走人物动作帧。
- 普攻、强化普攻、剑技的身体、武器和刀光全部来自原图，不叠加原来的程序化武器或剑弧。每个动作的接触帧对齐伤害时钟，闪避、受击、换人物会取消尚未发生的攻击。
- 法术保留原有 pixelfx 效果、伤害、资源消耗与冷却，人物的施法姿态采用新图中的姿态。

## 动作衔接

`assets/heroes/motion.json` 为八个新人物编排待机、三段攻击、剑技和收招；行走改为单独生成的 12 帧循环，攻击序列使用相邻的起手、挥击与跟随帧，不再在每段末尾插入待机。`heroFrameId()` 按每帧权重分配起手、释放和后续动作时间，同时保持接触帧与伤害时钟一致。连击首帧继承上一段末帧；松开攻击后经过 0.12–0.14 秒收招再回待机。新人物行走使用单独生成的 12 帧循环，并在停走切换时保留相位；步频随移速和模拟摇杆幅度变化。DNF 人物继续使用原有的行走序列与时钟。

按住普攻及自动战斗会等待当前剑技完成，避免普攻提前切断动作。闪避、受击与切换人物仍能取消动作。角色调色板缓存由各帧共用，避免连击切到新帧时重复计算颜色。

## 新人物的像素行走循环

八个新人物共生成 108 张新的行走姿态。`src/art/hero-walk-cycle.js` 使用 pixelfx 的原生像素 Painter：保留原造型的脸、服装、配色与自带武器，将双腿、鞋、空闲手臂、头发及衣摆分层后，逐帧渲染两骨骼腿部动作、脚跟/脚尖落地、摆臂、身体起伏和布料跟随。长袍角色按遮挡关系露出交替落地的脚部；生成文件保留透明背景，不在运行时拉伸身体贴图。

`assets/heroes/walk/rigs.json` 是可编辑的部件遮罩、关节与步幅配置。每个姿态在 192×192 源像素画布上渲染，脚底原点固定为 `[96, 180]`；12 帧按 4×3 网格输出。后腿阴影也使用该人物原有调色板，避免面部和衣服逐帧变色。帧周期根据步幅和默认移速计算，落地阶段的脚掌后移速度与人物前进速度相抵消。生成后打包进人物图集和代码像素数据，选人时提前解码行走帧。

```sh
node scripts/generate-hero-walks.mjs
python3 scripts/import-hero-sheets.py
python3 scripts/preview-hero-walks.py
npm run build
```

- `assets/heroes/walk/<hero>.png`：九张透明行走图集，每张 12 帧。
- `assets/heroes/walk/manifest.json`：源姿态、生成方式、每帧落脚位置、周期和像素哈希。
- `output/hero-previews/walk/all-heroes-walk.gif`：八个人物的行走预览。
- `output/hero-previews/walk/<hero>-contact.png`：逐帧检查表。

生成器读取当前代码像素数据中的基础姿态；若修改三张原始动作图，先运行一次导入脚本更新基础姿态，再执行上述生成与重新导入。其它攻击动作和五名 DNF 人物不参与行走生成。

## 本地切帧

```sh
python3 scripts/import-hero-sheets.py
```

依赖 Python 与 Pillow。脚本读取三张用户动作图、八张生成的行走图集，以及 `dnf-manifest.json` 对应的五张原有 DNF 图集，按标定行、人物中心与连接区域切帧，去除黑色背景，按帧压缩到最多 255 色，并保持武器与特效。原始 RGB 图片不变。DNF 图集直接保留原始合成武器与像素颜色，逐帧校验原有 RGBA 哈希，不再给身体叠加其它武器。由于源图不是带锚点的规则序列，脚底和身体中心使用提取配置对齐；原图未提供独立的受击、倒地动作时，复用对应的收招、低姿态帧。

生成文件：

- `assets/heroes/manifest.json`：13 个人物、武器、原始及生成帧的动作序列、接触帧、裁切区域、锚点和源文件 SHA-256。
- `assets/heroes/motion.json`：八个新人物的战斗动作编排；生成的行走帧由导入脚本注册。
- `assets/heroes/dnf-manifest.json`：五个 DNF 图集原有的帧、锚点及来源；DNF 素材保留 NEOPLE / NEXON 的原版权与本地非商业参考说明。
- `assets/heroes/<hero>.png`：透明图集，便于检查。
- `src/hero-pixel-data.js`：每帧调色板与 base64 字节索引，255 代表透明。浏览器同步解码，无需运行时读取 PNG。
- `output/hero-previews/`：检查用联系表，不参与游戏。

`src/hero-sprites.js` 负责解码与动作时钟映射，显示密度为每世界单位 2.7 源像素。颜色预设仍可在造型页使用；精确调色沿用原动作的 64 种常见颜色和槽位，生成行走帧共用相同颜色，不改变既有的调色配置。

人物身份与基础美术来自用户提供的素材；新增行走帧由像素代码在本地生成，没有从网络下载替代人物。来源记录与处理说明保存在 manifest 中。
